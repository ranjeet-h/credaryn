Authentic issuance, independently verifiable — from software to paper.

Credaryn is trust infrastructure for business documents. Seal a generated PDF with a standards-compatible PAdES signature, bind your business-critical claims, carry those claims onto paper as a signed machine-readable seal, and verify both through one normalized result — with no mandatory cloud service.

The problem isn't that documents can be edited.

PDFs, images and paper will always be editable. The real problem is that a recipient has no simple, independent way to know what the issuer actually issued — or whether the visible document was altered.

Credaryn makes that verification boring.

One developer-facing layer orchestrates established standards, adds the missing browser-and-paper bridge, and returns one result a recipient can understand.

Top features

Everything needed for cross-medium document trust

🔐

PAdES PDF signatures

Baseline B-B through an isolated EU DSS 6.5 adapter, optional B-T with an RFC 3161 TSA. No DSS/Java types leak into your code.

📄

Bound business claims

Money as integer minor units plus ISO currency, never floating point. High-value claims are bound into the signed representation.

🧾

Paper Seal Profile v1

CRD1: + Base45 + deterministic CBOR + COSE_Sign1 + ES256, QR error-correction M, fail-closed 1200-byte limit.

✅

One verification result

VALID_TRUSTED, VALID_UNTRUSTED, INVALID, UNVERIFIABLE — across PDF, CRD1 text and QR images.

🏢

Enterprise trust

Configured public keys, X.509 anchors and did:web, with the real trust method reported. Fetched never means trusted.

🔑

KMS / HSM signers

AWS KMS, Google Cloud KMS, Azure Key Vault / Managed HSM and PKCS#11 — all ES256, private keys never leave your provider.

🖨️

Browser printing

Prepare a page with a signed QR seal before printing, and report PAPER_CLAIMS_ONLY — no false claims about OS print bytes.

🧩

Embeddable verifier

A framework-neutral Web Component plus a self-hosted PWA and versioned REST API, one shared engine.

📦

Self-hostable

Docker Compose reference deployment with optional PostgreSQL status/admin profiles and an air-gapped override. No Credaryn SaaS dependency.

How it works

Standards underneath. Simplicity on top.

01

Describe

A normalized DocumentDescriptor: issuer, document id, type, time and flat claims.

02

Sign

The signer stays in your KMS/HSM. PDF → PAdES; claims → COSE_Sign1 with ES256.

03

Carry

Place the signed paper seal, then apply the PAdES signature to the final artifact.

04

Verify

Detect input, verify the signature, resolve trust separately, optionally check lifecycle.

issue.ts
// one call: seal the PDF and bind the claims
const sealedPdf = await credaryn.sealPdf(pdfBytes, {
  issuerId: "acme-retail",
  documentId: "INV-2026-82919",
  documentType: "invoice",
  issuedAt: "2026-09-18T00:00:00Z",
  claims: { invoiceNumber: "INV-2026-82919",
            totalMinor: 1180000, currency: "INR" },
});
verify
# CLI
pnpm credaryn verify sealed.pdf --trust ./trust

# REST (self-hosted, anonymous read-only)
curl -F file=@sealed.pdf \
  http://localhost:8080/v1/verify/pdf

Verification result model

Facts stay separate — never one word: “authentic”.

VALID_TRUSTED

Checks pass and the issuer chains to a configured trusted identity.

VALID_UNTRUSTED

The signature is valid but the issuer is not trusted here. Never labelled authentic.

INVALID

A signature, an integrity check or a signed-claim binding failed.

UNVERIFIABLE

Required evidence is missing, unsupported or cannot be resolved.

Lifecycle (ACTIVE · REVOKED · CANCELLED · SUPERSEDED · EXPIRED · UNCHECKED) and security mode (DIGITAL_ARTIFACT_SIGNED vs PAPER_CLAIMS_ONLY) are independent fields.
