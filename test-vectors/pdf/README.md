# PDF vectors

These vectors are generated by the Puppeteer invoice example and validated by
the isolated European Commission DSS 6.5 adapter. The signed vector contains
the visible Paper Seal QR and the human-readable `CRD1:` transport before its
PAdES signature is applied. No private key or certificate secret belongs here.

## Fixtures

| File | SHA-256 | Expected DSS result |
| --- | --- | --- |
| `invoice-11800.pdf` | `0431be4d4d844e9516d9d0ceef84d0adf701a3f550ff2127f20c01635564f380` | `cryptographicValidity=VALID`, `artifactIntegrity=VALID`, `signatureLevel=B-B` |
| `invoice-11800-mutated.pdf` | `457124278a8d05d6abfbdab459638da56aa74de6eb68f2b9763364571a70fc7e` | `cryptographicValidity=INVALID`, `artifactIntegrity=INVALID` |

The demo DSS key is generated inside the container and is intentionally not a
repository trust anchor. The embedded certificate lets DSS validate the
signature independently of the current container key.

## Recreate and verify

```bash
docker compose -f adapters/pades-dss/docker-compose.yml up -d --build
pnpm --filter @credaryn/example-invoice-puppeteer generate
pnpm --filter @credaryn/example-invoice-puppeteer verify:fixtures
shasum -a 256 test-vectors/pdf/*.pdf
```

The generated signed bytes may change when the DSS demo key or renderer
changes. Update the hashes only after manually inspecting the PDF and
recording the DSS original/mutation results in the milestone verification log.
